# Template — Release Checklist

This is a **publication acceptance gate**. Mark items complete only after observing the specified result.

## Playable package

- [ ] Critical route starts, advances and ends in a fresh standalone executable.
- [ ] Correct target platform, binary, content and dependency packaging verified.
- [ ] Input, movement, camera, collision and menu focus pass human review.
- [ ] Key gameplay changes persist after a fresh-process Save/Load when applicable.
- [ ] Player cannot be stranded after irreversible actions.
- [ ] Current UI/HUD, sounds and effects are visible/audible in the package.
- [ ] Performance tested at the intended hardware class and graphics settings.
- [ ] All known release blockers addressed or transparently documented.

## Publication and rights

- [ ] Current official platform/competition rules checked against this event.
- [ ] Original and sourced assets have recorded permission and required attribution.
- [ ] Player-facing texts, age/content rating, supported languages and controller information verified.
- [ ] Credits, license notices and third-party inventory are accurate.
- [ ] Screenshots and a **genuine gameplay** video were captured from the relevant build.
- [ ] Any required public development log is reachable without private sign-in.
- [ ] Release files, size/hash where needed and destination listing verified.
- [ ] Authorized human submits or publishes; downloaded artifact is tested.

## Documentary closeout

- [ ] Each mandatory feature has clear evidence status.
- [ ] Removed or unfinished features are recorded as cut/deferred, not silently represented as complete.
- [ ] Final commit/build identity and test results are retained.
- [ ] Postmortem records actual outcomes and future maintenance risks.

A completed checklist is a documented release claim **only when backed by evidence**.
