# T15 Example — Real Restoration Presentation Using Existing T07 State

This educational example adds a **functional three-piece native restoration animation** to the existing [T07 SaveGame/run subsystem](../savegame-ab/README.md). The actor also activates a **real Niagara System** once it has been authored and assigned in the Unreal Editor; the Niagara asset itself is not stored as fake text or autogenerated `.uasset` bytes.

**Publication status:** Original C++ source and integration instructions are published. The source has **NOT RUN** through UHT/UBT in an installed UE 5.9 project, and no actual Blueprint, Niagara System, PIE, Chaos Cache, Windows package or human acceptance was performed during publication. **Do not claim an engine build pass from source-level inspection.**

## Files and responsibilities

| File | Concrete behavior |
| --- | --- |
| [`GPPDemoRestorationPresenter.h`](Source/GPPDemoRestorationPresenter.h) | One visual-only Actor with three actual `UStaticMeshComponent` pieces, a `UNiagaraComponent`, a stable BeaconId and bounded playback duration |
| [`GPPDemoRestorationPresenter.cpp`](Source/GPPDemoRestorationPresenter.cpp) | Loads a real built-in Engine Cube as an educational mesh, creates visual pieces, binds to two T07 events, projects saved state, animates transforms, triggers assigned Niagara, handles stream-out/end play |
| [T07 `GPPDemoRunSubsystem.h`](../savegame-ab/Source/GPPDemoRunSubsystem.h) | Declares `FGPPDemoBeaconRestored` and `OnBeaconRestored` in the **existing** progression authority |
| [T07 `GPPDemoRunSubsystem.cpp`](../savegame-ab/Source/GPPDemoRunSubsystem.cpp) | Broadcasts the fresh-commit event only after a real `TryDonateLight` succeeds; load/new game/checkpoint updates do not emit it |

The three pieces are visible before restoration at deliberately offset locations and move into their Editor-defined final locations during a two-second easing animation. **Their collisions are disabled in C++ on purpose.** Physical traversal is always governed by the real gate/bridge already implemented elsewhere.

## Integration in an actual Unreal C++ project

1. Inspect the current module and existing run/progression/presentation classes. Reuse a valid implementation rather than install two run authorities. The source assumes the original T07 sample is part of the **same module** and its classes keep their source names; if using a different authoritative service, adapt imports/event bindings to that service instead.
2. Enable and verify the installed **Niagara** plugin in the project. In the existing game module `YourProject.Build.cs`, append the actual module name `Niagara` to the existing dependency list (together with the module's already-required `Core`, `CoreUObject`, `Engine`). Do not replace the dependency list or create a new empty module.
3. Copy the two `Source/` C++ files into your existing module next to the existing T07 source. The T07 header/source already contain the fresh-commit delegate; do not add a duplicate class, a second tag authority or another subsystem.
4. Build with the [T02 local Win64 build procedure](../../tutorials/unreal-project-bootstrap-local-build.md) and inspect UHT/UBT errors. Restart/reload the Editor as needed to expose the compiled native Actor.
5. In the **authorized map**, create a Blueprint child of `AGPPDemoRestorationPresenter` in the project-owned Content namespace. Place **one instance** next to an actual T07 beacon. Match `BeaconId` exactly to the `FName` provided to `TryDonateLight`, e.g. `DemoBeacon` in both places.
6. Observe that `LeftPiece`, `CenterPiece` and `RightPiece` have actual Engine Cube meshes (not empty mesh slots). Position their inherited components as the final assembled shape. The Actor caches these final transforms on BeginPlay; the broken state is computed by applying native offsets.
7. Create/save a real **Niagara System** from the installed `Simple Sprite Burst` template under your own Content path. Make it a short, nonlooping burst with bounded particles. Assign the saved system to the inherited `RestorationFX` component. Its `Auto Activate` must remain false. Confirm the Niagara content reference survives Editor restart.
8. Keep the real T06 pickup, hold-confirm interaction and T07 donation caller intact. **There is no automatic donation in this Actor.** The player must execute a valid transaction for the new event to fire. Call `StartNewRun` with a valid map and safe checkpoint, collect the offering, then confirm `TryDonateLight(BeaconId)`; do not bypass validation to make the VFX appear.
9. Confirm that the authoritative gate independently calls `IsBeaconPowered(BeaconId)` on its own BeginPlay and progress changes to update Pawn-blocking collision. If that gate does not exist, the **visual demonstration still functions**, but a playable gate-restoration feature cannot be marked integrated.
10. Test valid/invalid actions, load, streaming and packaging against [T15's full verification matrix](../../tutorials/niagara-chaos-deterministic-restoration.md). Save only your authorized Blueprint/map assets after inspecting unsaved work; never overwrite a different agent's session.

## Runtime contract

- `OnProgressChanged`: snap all pieces to the current state and stop one-shot FX. Called for normal progress changes, New Game, snapshot reads and other projections.
- `OnBeaconRestored`: **only** from fresh successful `TryDonateLight`, after the progress projection; start three-piece animation and the assigned Niagara system. No duplicate event is emitted for a failed repeat donation.
- Streamed-in Actor: bind to the GameInstance-owned run service and immediately project correct state at BeginPlay. Does **not** replay VFX.
- Streamed-out Actor: unbind both events and deactivate the Niagara component. A stream-out must not roll back the restored world.
- Loading during playback: the progress event snaps to the selected durable state without a new burst.
- Disabled/unassigned Niagara: the mesh animation remains real. The VFX portion of acceptance stays NOT RUN/FAIL until an actual system is authored and verified.
- Crash or missing module: report as a genuine build/integration failure, not as a cosmetic fallback.

The native actor **does not** simulate Chaos or install an untested cache. See the [T15 optional Chaos exercise](../../tutorials/niagara-chaos-deterministic-restoration.md) for a real Geometry Collection authoring path, verification of plugin capabilities and a separate cosmetic cache. Do not present Chaos as executed until that exercise runs.
